# 二、基础要求（必达线）

## B1 · 多维交互控制检测 [出处:要求]

> 原文："自主设计演奏交互形态，基于各类传感器实现演奏动作精准采集，支持选音、触发、拨弦、力度感应等操作，具备至少 2 个独立可控维度，交互逻辑灵敏稳定，适配乐器演奏场景。"

**拆解：**

| 子项 | 内容 | 性质 |
|---|---|---|
| B1.1 | **自主设计**演奏交互形态 | 必须 |
| B1.2 | 基于**各类传感器**实现演奏动作精准采集 | 必须 |
| B1.3 | 支持**选音** | 必须 |
| B1.4 | 支持**触发** | 必须 |
| B1.5 | 支持**拨弦** | 必须 |
| B1.6 | 支持**力度感应** | 必须 |
| B1.7 | 具备**至少 2 个独立可控维度** | 必须（数量硬指标） |
| B1.8 | 交互逻辑**灵敏稳定**，适配乐器演奏场景 | 定性 |

**❓模糊点**：
- "B1.5 拨弦"与"B1.4 触发"的区别未定义。拨弦是否可理解为"带力度包络的触发"？
- "**独立可控**维度"未给判据。两个维度是否要求物理量不同、互不干扰？原文无定义。
- B1.3~B1.6 四项是**并列必须**，还是"等操作"中的举例？

## B2 · FPGA 纯硬件实时音频合成 [出处:要求]

> 原文："完整音频生成通路全部基于 FPGA HDL 硬件逻辑实现，支持逐样本实时音频运算，可采用波表采样、加法合成、FM 调频、物理建模等任意方案；严格控制演奏延迟，实现控制信号到音频输出总延迟 ≤10ms，杜绝软件串行运算滞后问题。"

**拆解：**

| 子项 | 内容 | 性质 |
|---|---|---|
| B2.1 | **完整音频生成通路全部**基于 FPGA **HDL 硬件逻辑**实现 | 必须（红线） |
| B2.2 | 支持**逐样本**实时音频运算 | 必须 |
| B2.3 | 算法可选：波表采样 / 加法合成 / FM 调频 / 物理建模 等 | 自由选择 |
| B2.4 | **控制信号到音频输出总延迟 ≤10ms** | **必须（数值硬指标）** |
| B2.5 | 杜绝**软件串行运算滞后** | 必须 |

**❓模糊点**：
- "≤10ms"的**测量边界**未定义：是从传感器变化算起，还是从 FPGA 内部信号算起？是否含 DAC 重建延迟？
- "完整音频生成通路"的**范围**未定义：是否含效果器？是否含 I2S 发送模块？

## B3 · 合规实时发声与多复音能力 [出处:要求]

> 原文："系统基础复音数 ≥4，支持四路及以上独立声部同时并发发声。严格遵循赛题合规要求：所有输出音频均由 FPGA 根据实时演奏指令逐音、逐样本实时生成，支持单音实时变调、ADSR 包络调控、多声部实时混音，严禁直接播放预录 PCM 音频、预置推流及整段录音触发，保障实时合成核心属性。"

# 四、核心评分规则与现场验证标准 [出处:评分]

> 这一节**决定分数怎么算**，与前面的"要做什么"是两个不同维度，需单独对待。

## R1 · 振荡器统计规则

> 原文："独立发声单元为包含**独立相位累加器、频率调控、包络控制**的完整振荡器；单波表采样查表不计多谐波数量，仅计单个振荡器；加法合成按运算分量统计、FM 按调制运算器统计、物理建模按并行弦/模态单元统计。"

| 子项 | 内容 | 影响 |
|---|---|---|
| R1.1 | 独立发声单元 = 独立**相位累加器** + **频率调控** + **包络控制** | **计数判据（三要素齐全）** |
| R1.2 | 单波表采样查表**不计多谐波数量**，仅计**单个**振荡器 | **限制**：波表查表不能靠"表内有多个谐波"多计数 |
| R1.3 | **加法合成按运算分量统计** | 计数方式 |
| R1.4 | **FM 按调制运算器统计** | 计数方式 |
| R1.5 | **物理建模按并行弦/模态单元统计** | 计数方式 |

**关键影响**：这意味着**算法的选择直接改变"能数出多少个振荡器"**。同样的硬件资源，不同算法的计数倍率不同。

**❓模糊点**：
- R1.2 中"仅计单个振荡器"是指**每次查表**只计 1，还是**每张表**只计 1？
- 若一个声部用了波表 + FM 组合，如何计数？原文未说明组合情况的规则。

## R2 · 系统吞吐量指标

> 原文："以「**同时活跃可闻独立振荡器总数 × 实际音频输出采样率**」为核心评分依据，**过采样不叠加加分**。"

| 子项 | 内容 | 影响 |
|---|---|---|
| R2.1 | 核心评分 = **同时活跃可闻独立振荡器总数 × 实际音频输出采样率** | **这是分数的直接公式** |
| R2.2 | **过采样不叠加加分** | 提高采样率**不会**提高分数 |

**推论（供参考，非决策）**：
- 分数 = 振荡器数 × 采样率，两个因子**都可提高分数**。
- 但 R2.2 明确"过采样不叠加"，即**不能靠把采样率标到 96k/192k 来刷分**。
- R2.1 中的"**实际**音频输出采样率"与"同时活跃**可闻**"两个限定词值得注意 —— 强调"真实可听到的"。

**❓模糊点**：
- 若采样率提高到 48k→96k 但振荡器数不变，是否完全不加分？还是"按实际输出采样率算但不额外奖励过采样"？原文表述可两解。
- "同时活跃可闻"如何判定？是否要求每个振荡器都能被独立听到/辨出？

## R3 · 现场验证要求

> 原文："支持**测试模式**下输出多路不同频率音频，频谱可观测对应数量**独立谱峰**，同时可通过 **RTL 代码**佐证纯硬件实时合成通路，验证**无预录音频播放**行为。"

| 子项 | 内容 | 性质 |
|---|---|---|
| R3.1 | 支持**测试模式** | **必须（否则无法自证）** |
| R3.2 | 测试模式下输出**多路不同频率**音频 | 必须 |
| R3.3 | 频谱可观测对应数量的**独立谱峰** | 验证方法 |
| R3.4 | 可通过 **RTL 代码**佐证纯硬件实时合成通路 | 验证方法 |
| R3.5 | 验证**无预录音频播放**行为 | 验证目的 |

**关键影响**：R3 是**验证机制**而非功能要求。但 R3.1 的"测试模式"若不实现，R3.3/R3.4/R3.5 的验证就无从谈起 —— 实际等同于**必须实现**。
