# 决策登记与延后策略

> 目的：**让尽可能多的决策可以延后**，只在真正必要的时候才拍板。
>
> 判据：一个决策是否"现在必须定"，取决于**晚定的返工成本**，而不是它重不重要。

---

## 一、决策分三类

| 类别 | 含义 | 处理方式 |
|---|---|---|
| 🟢 **可无限延后** | 定了也不影响别的模块，改起来是局部改动 | 用到时再定 |
| 🟡 **可延后，但需预留接口** | 晚定会改接口 → 会牵连别的模块 | **现在只定接口，实现留空** |
| 🔴 **真阻塞** | 不定就无法开工 | 必须早定 |

---

## 二、真阻塞项：只有 2 个

### 🔴 B-1 · DAC 模块

**为什么真阻塞**：不是"决策"，是**事实 + 采购**。没有它就没有声音，没有声音就没有任何验证手段。

但它**只阻塞 P3 及之后**。P1（工具链）、P2（单声部引擎）完全不受影响。

**所以**：这不是"要现在决定什么"，而是"**要现在下单**"。下完单就不用管了。

### 🔴 B-2 · 声部模块的接口定义

**为什么真阻塞**：`voice.v` 是 P2 的核心，它的端口一旦定了，P4（多声部）、P5（交互层）都按它接。

**但这不需要你决定** —— 接口是技术产物，我可以按"未来可能扩展"的原则先定好。

---

## 三、可延后项：逐条给出"延后方案"

### 🟡 S8 · 纯波表 vs 波表+加法混合

**晚定的后果**：如果先做了纯波表，后来要加加法合成，`voice_osc.v` 内部要重写。

**延后方案（把返工变成扩展）**：

现在的 `voice_osc.v` 只需要满足一个最小契约：

```verilog
module voice_osc #(
    parameter PHASE_ACC_BITS = 32,
    parameter PHASE_IDX_BITS = 12,
    parameter SAMPLE_W       = 16
) (
    input  wire clk,
    input  wire rst_n,
    input  wire sample_en,              // 48kHz 单周期脉冲
    input  wire [INC_W-1:0] inc,        // 频率控制字
    input  wire run,                    // 门控
    output reg signed [SAMPLE_W-1:0] sample
);
```

**关键**：把"取什么波形"**挪到模块外面**（通过 `wavetable` 输入或参数），
这样以后加加法合成 = 新增一个 `voice_add.v`，**原来的 `voice_osc.v` 一行不改**。

→ **现在只需要采纳这个接口，S8 可以无限延后。**

### ✅ S1 · 3 个维度的最终定义（已确认）

**当前结论**：v1.0 使用以下三条输入线：

```text
Pitch Bend       <- 摇杆左右
力度 / 动态      <- 超声波手距
扫弦间隔 / 琶音  <- 摇杆前后，和弦触发时锁存
```

`input_map.v` 仍然只输出**语义化信号**，不输出“哪个传感器”：

```verilog
output wire [6:0] note_select;      // 选音
output wire [7:0] velocity;         // 力度
output wire [7:0] expression;       // 连续表情
output wire signed [7:0] pitch_bend;// 音高弯音
output wire [7:0] strum_interval;   // 和弦扫弦间隔
output wire       trigger;          // 触发
output wire       pluck;            // 拨弦
```

**上游是什么传感器，`input_map.v` 不关心。**
→ 板载按键、触摸、超声波、光敏，都可以后接进来。S2/S3 触摸细节仍可延后。

### 🟢 S2 · 触摸方案（RC 测时 vs 555 计频）

**晚定的后果**：只影响 `touch_sense.v` 的内部实现和电路搭建。

**延后方案**：`touch_sense.v` 对外只输出 `touch[11:0]` 位掩码。内部换实现，外部无感。

→ **到 P5B 再定。**

### 🟢 S3 · 触摸键数量

只影响 `touch_sense.v` 的参数和电路规模。**到 P5B 再定。**

### ✅ S4 · 超声波映射（已确认）

超声波映射到力度 / 动态：note-on 时锁存 `velocity`，持续按住时更新平滑后的
`expression`。靠近更强、远离更弱；不驱动快速滑音。详细定义见
`docs/16_V1范围与输入语义.md`，测距实现与异常恢复见
`docs/17_P5C超声波设计.md`。

### 🟢 S5 · 波表张数/长度

只影响 `gen_wavetable.py` 的参数和 BSRAM 占用。**到 P1 写工具时顺手定，给默认值即可。**

初始默认：**4096 点 × 16 bit × 4 张**（正弦/锯齿/三角/方波）。

### 🟢 S6 · ADSR 参数固定还是可调

**晚定的后果**：只影响参数从哪来。

**延后方案**：`voice_adsr.v` 的 A/D/S/R 一律做成**输入端口**。
固定值 = 顶层绑常量；可调 = 顶层接寄存器。**两种都是零返工。**

→ **到 P4 再定。**

### 🟢 S7 · 声部分配策略

只影响 `voice_alloc.v` 内部逻辑。**到 P4 再定。**

### 🟢 H1 · 板子状态

不是决策，是事实。**只影响 P3 何时能开始，不影响 P1/P2。**

### 🟢 H3 · 自研元件

只影响 P5B/P5C。**到 P5 之前买齐即可。**

### 🟢 H4 · 示波器/频谱仪

只影响 P6 的验证手段。**到 P6 再想办法**（手机频谱 App 也可以）。

### 🟢 技术细节（波表位宽、相位累加器位宽、测试音频率等）

全是技术推导产物，**我按需求算就行，不需要你参与**。

## 四、汇总：延后是否安全的判断表

| 决策 | 类别 | 最晚何时定 | 延后是否安全 |
|---|---|---|---|
| DAC 模块 | 🔴 阻塞 | **现在**（下单） | ❌ 不安全 |
| 声部模块接口 | 🔴 阻塞 | 写 P2 之前 | ❌ 不安全（但由我定） |
| S8 波表/加法 | 🟡 | 写 `voice_osc.v` 之前 | ✅ 安全（接口隔离后） |
| S1 三维定义 | ✅ 已确认 | 已完成 | Pitch Bend / 力度动态 / 扫弦间隔 |
| S2 触摸方案 | 🟢 | P5B | ✅ 安全 |
| S3 触摸键数 | 🟢 | P5B | ✅ 安全 |
| S4 超声波映射 | ✅ 已确认 | 已完成 | 力度 / 动态 |
| S5 波表参数 | 🟢 | P1 | ✅ 安全（给默认值） |
| S6 ADSR 可调 | 🟢 | P4 | ✅ 安全 |
| S7 分配策略 | 🟢 | P4 | ✅ 安全 |
| H1 板子状态 | 🟢 | P3 | ✅ 安全 |
| H3 自研元件 | 🟢 | P5 | ✅ 安全 |
| H4 示波器 | 🟢 | P6 | ✅ 安全 |

**结论：真正需要现在处理的只有"下单 DAC"这一件。**

## 五、接口预留清单（这是"延后"能成立的前提）

要让上面的延后成立，以下接口**必须现在就设计对**：

| 模块 | 接口契约 | 隔离了什么决策 |
|---|---|---|
| `voice_osc.v` | `clk / rst_n / sample_en / inc / run / sample` | 隔离 S8（波形来源） |
| `voice_adsr.v` | `gate / A / D / S / R / level` | 隔离 S6（参数来源） |
| `input_map.v` | `note_select / velocity / expression / pitch_bend / strum_interval / trigger / pluck` | 隔离 S2/S3（传感器类型） |
| `mixer.v` | 输入声部样本数组 → 输出单样本 | 与声部数解耦 |
| `synth_top.v` | `parameter VOICES` | 隔离复音数 |

**只要这 5 个接口定对，表格里所有 🟡🟢 项都可以安全延后。**

## 六、操作约定

**做每个阶段前，只回答该阶段必需的决策。**

| 阶段 | 需要先定 |
|---|---|
| P0 | 无（只需下单 DAC） |
| P1 | S5（波表参数，给默认即可） |
| **P2** | 无 ← **接口已隔离** |
| P3 | H2（DAC 型号，到货后自然知道） |
| P4 | S6、S7 |
| P5A | 无 |
| P5B | S2、S3 |
| P5C | ✅ S4 已确认，直接实现力度 / 动态映射 |
| P5D | ✅ S1 已确认，直接合并三条输入线 |
| P6 | H4（验证手段） |

> 注意：S1 和 S4 已经在本阶段确认，后续 P5C/P5D 不再需要等待这两个决策。

---

## 七、唯一建议现在做的事

| 事项 | 理由 |
|---|---|
| **下单 DAC 模块** | 它是唯一影响关键路径的采购项，且发货需要时间 |
| 板子下单（如未下） | 同上 |
| 其余全部 | **可以延后** |

> 其余的决策，等做到对应阶段时，你会**比现在有更多的信息**（比如板子到了、声音出来了、资源报告有了），
> **那时做的决定质量更高。**
