## 1. 一句话任务

给**新到货的 SPI 版大屏 OLED** 写一套驱动与界面：**横屏显示**，上半屏是**示意波形动画**
（随音色/音高/力度/摇杆响应），下半屏分**三列**（TONE / FX / MODE），每列有表头、
选项列表、选中项反白，右上角显示**调式**；并保留每列底部对应的按键提示。

**本轮范围**：显示驱动 RTL（SPI）、帧缓冲与绘制、界面渲染、波形发生器，以及配套仿真。
**不在本轮范围**：音频通路改动（`synth_engine`/`voice` 等）、正式 `loom_top`、
触摸/旋钮的硬件设计（那是 `docs/20` 的任务）。

## 3. 关键设计约束（已讨论定稿，直接照做）

### 3.1 分辨率与刷新预算（以 128×64、SPI 10 MHz 计）

| 项 | 数字 | 说明 |
|---|---|---|
| 帧缓冲 | 128×64/8 = **1 KB** | 放 BSRAM（全器件 828 Kbit，现在才用 9/46 块） |
| 全屏刷新 | ≈ **1 ms** | 1 KB × 8 bit / 10 MHz，足够 100+ fps |
| 局部刷新 | 波形区 128×32 = 512 B ≈ 0.5 ms | **推荐**：上半波形与下半列表分开刷，互不干扰 |
| 字模 | 建议 **6×8 ASCII**（含数字 5–8、字母全 A–Z） | 旧字模缺 `5 6 7 8` 与 `L` 等（见 `docs/19` 案例 7 区的经验），这次一次补全 |
| 复位时序 | RES 低电平 ≥ 3 µs，之后延时 ≥ 100 ms 再发初始化 | 按 SSD1306 datasheet |

### 3.2 界面布局（128×64 横屏，坐标以左上角为原点）

```text
 +--------------------------------------------------------------------+ y=0
 |                                                                    |
 |   波 形 区（上半屏，y=0..31）                                        |
 |     示意波形：形状=音色，波长=音高，幅度=力度/摇杆                    |
 |                                            调式（右上角 2 字符）    |
 |                                                                    |
 +--------------------------------------------------------------------+ y=32 分隔线
 | TONE:SINE   | FX:CHORUS   | MODE:TRI      |  表头行（每列 42 px）   | y=33..40
 | >SINE       |  DRY        |  ONE          |  选项（选中 = 白底黑字） | y=41..48
 |  SQUARE     | >CHORUS     | >TRI          |                        | y=49..56
 +--------------------------------------------------------------------+ y=57
 |  BTN1       |  BTN2       |  BTN3         |  列底按键提示           | y=57..63
 +--------------------------------------------------------------------+ y=63
```

要点：

- 三列宽度各 **42 px**（约 7 个 6×8 字符），列间留 1 px 分隔；
- **选中项反白**（白底黑字）用于区分当前选项；
- 每列底部对应的物理按键（`docs/15` §7：音色键 / 效果器键 / 模式键）**按一次向下选一项**，到底回卷；
- 调式（`docs/15` §7 的 12 档旋钮）显示在**右上角**，1–2 个字符，允许覆盖波形一角；
- 页面上端波形区**只画示意波形**，不读真实音频采样（避免抽取/混叠，也避免"像示波器"的误解）。

### 3.3 示意波形发生器（在显示模块内部实现，约 200 LUT）

| 参数 | 来源 | 映射 |
|---|---|---|
| 波形形状 | `timbre`（正弦 / 方波） | 正弦 = 正弦查表；方波 = 符号函数 |
| 波长（像素） | 当前音高 | 低音一屏 2~3 个周期，高音一屏 6~8 个周期，**变化做插值避免跳变** |
| 幅度 | 力度 / 摇杆 expression | 0~满幅线性映射（摇杆推动时波形实时变胖/变瘦，这是"交互感"的来源） |
| 相位推进 | 固定显示频率（几 Hz 级） | 视觉上"缓缓流动"即可，与真实 440 Hz 无关 |

> ⚠️ 报告与答辩必须说明：**这是示意波形，不是真实音频采样**（`docs/19` 案例 15 的合规口径同理，避免被误解为伪造）。

### 3.4 软件/硬件分工边界（合规）

- OLED 驱动 IC（SSD1306/SH1106）是**固定功能专用芯片**，不参与音频生成 ✓ 合规；
- **不得**在显示链路引入任何 MCU / 可编程器件（`AGENTS.md` 第五节 + `docs/19` 案例 15）；
- 显示**只读**演奏状态，**不反向修改音频参数**（`docs/16` §5）。

## 4. 交付物与格式约定

| 交付物 | 格式 | 要求 |
|---|---|---|
| UI 像素布局 | **本文档 §3.2 的 ASCII 图 + 坐标表**（必要时再给 SVG） | 协作方可逐像素核对 |
| 状态总线定义 | Markdown 表（位宽、含义、来源模块） | 便于与 `input_map` 对接 |
| 字模表 | Verilog `case` 或 `.hex`（可复现生成脚本更好） | 要包含数字 0–9 与 A–Z |
| 驱动 RTL | `rtl/display/oled_spi.v`（新模块，**不改**旧 `oled_sh1106.v`） | 旧模块继续给 1.3″ 调试屏用 |
| 仿真测试台 | `sim/tb_oled_spi.v` 等 | 覆盖：SPI 时序、初始化序列、帧缓冲读写、界面渲染、局部刷新窗口 |
| 工程 | 新建 `fpga/oled_ui_demo/` | 不动 `loom_top` / `p5a_demo` / `timbre_fx_demo` / `p6_test_demo` |
