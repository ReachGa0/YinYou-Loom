## 一、硬件

| 项目 | 内容 |
|---|---|
| 模块 | 1.3 寸 4 针 OLED（I2C），丝印针序 `GND VCC SCL SDA` |
| 手册 | `1.3OLED显示屏_数据手册.pdf`（Allvision QG-2864KSWLG01） |
| 接线 | VCC→3V3，GND→GND，SCL→PIN52，SDA→PIN53 |
| 实测 | 模块供电 3.3V 正常；模块背面有上拉电阻 |

**手册自相矛盾**（重要）：

| 位置 | 说法 |
|---|---|
| 机械图（P5） | `Driver IC: SSD1306` |
| 命令章节（P20） | "Refer to the Technical Manual for the **SH1106**" |
| 初始化示例 | 用 `0xAD`（SH1106 专有电荷泵命令） |
| I2C 地址（P19） | `0111100b` = 0x3C；若 D/C# 接 VDD 则为 0x3D |

另外：手册第 21–27 页的「例子」是**并口（6800/8080）**代码（用 DC/CS/WR），
不是 I2C 代码，对 I2C 驱动没有直接参考价值；但其中的**命令值**可直接采用。

## 三、已排除的怀疑

- ❌ 不是"FPGA 没运行"——心跳 LED 正常
- ❌ 不是"没有 I2C 波形"——SCL 活动 LED 正常

- ❌ 不是"模块没供电"——实测 VCC 3.3V

## 四、仍未排除（下次继续时按序查）

1. **排针物理位置插错**（最大嫌疑）
   40P 排针是两排，PIN52/53 的实际位置需对照 Sipeed wiki 引脚图核对。
   → 拔下 SCL/SDA，按引脚图重新插一遍
2. **模块本身故障**
   最省事的判定：用 Arduino / 树莓派 + 现成 OLED 库试一次。那边也不亮 → 模块坏
3. **PIN52/53 的复用限制**
   这两个脚在芯片内部是 SSPI 专用脚，已在 Gowin 里勾选 `Use SSPI as regular IO`
   才能布局；但**该选项是否真的让它们在运行时按普通 IO 工作，尚未验证**
   → 可换到 PIN71/72 等非复用脚再试
4. **SDA 输出/输入路径**
   尚未用示波器或逻辑分析仪直接观察 SDA 波形
