# FPGA 工程实践与踩坑记录

> 状态：活文档，**每解决一个非平凡问题就地追加一条**
> 用途：**答辩前的复习材料**。重点不是"我们做出来了什么"，而是"我们踩了什么坑、
> 怎么定位、为什么这样解决、这件事教给我们什么关于 FPGA 的道理"。
> 阅读方式：每条都按 **现象 → 定位过程 → 根因 → 解决 → 启示** 五段写。
> 涉及数字的地方都标了证据来源（仿真输出 / 综合报告 / 实机听感），可复现。

## 案例 1 · 48 kHz 音频时钟：连续推翻两次方案

**现象**：最初打算 100.8 MHz 主频，分频出 4.608 MHz 位节拍；综合前算比例时发现数学上做不到。

**定位过程**：把 Gowin rPLL 的约束逐条套上——
`f_CLKOUT = f_CLKIN × FBDIV / IDIV`、`f_VCO = f_CLKOUT × ODIV`、`fPFD = f_CLKIN / IDIV`，
且 `FBDIV ≤ 64`、`IDIV ≤ 64`、`fPFD` 必须落在 3–500 MHz。

**根因**：

| 尝试 | 问题 |
|---|---|
| 100.8 MHz | 需要 224/15 或 448/15 的比例，**超出 FBDIV/IDIV 的 64 上限** |
| 69.12 MHz | 数学可达，但 `fPFD = 27 / 25 = 1.08 MHz`，**低于 Gowin 要求的 3 MHz 下限**，布局布线必然报错 |
| **72 MHz（最终）** | `27 × 8 / 3 = 72`，`fPFD = 9 MHz`，`VCO = 576 MHz`，全部落在合法区间 |

**解决**：72 MHz 主频 + `frac_div(8/125)` 产生平均 4.608 MHz 位节拍；I2S 每帧 48 个 BCLK
→ 长期平均采样率 **48.000 kHz 精确**。

**启示**：
1. **PLL 是"带约束的数学题"**，不是"填个想要的值"。要先算边界（FBDIV/IDIV/fPFD/VCO），再谈精度。
2. 想要非整数倍频率时，**"主频 + 分数分频"比"硬凑一个奇怪的主频"稳得多**；
3. 这类失败**必须记下来**：它证明我们理解了器件约束，而不是碰巧能跑。

## 案例 2 · PLL 参数被 IP 向导悄悄改掉

**现象**：手填的 IDIV/FBDIV 在重新生成 IP 后被改成了别的值。

**根因**：Gowin IP Wizard 偏好"简洁比值"，会归一化用户输入。

**解决**：不再用向导重新生成；以 `fpga/loom/src/gowin_rpll/gowin_rpll.v` 里的 `defparam` 为唯一事实来源，
并在 `README` 里明确写"勿再打开向导重新生成"。

**启示**：**生成式工具的产物要当成"外部输入"来校验**。工具帮你"优化"过一次，你的设计文档就与代码脱钩了。

## 案例 3 · 波表没被推断成 BSRAM

**现象**：预期波表占用块存储，实际综合报告显示落在 LUT 里（P2 遗留项，移到 P3 才验证）。

**根因**：存储推断（inference）对代码风格敏感——读地址是否同步、是否有复位、复位值是否可映射等。

**解决**：按同步读 + 无复位数据路径的写法组织 `wavetable_rom.v`，并用综合报告确认 BSRAM 块数。

**启示**：**"存大数组"不等于"用块存储"**。唯一可信的判据是综合报告里的 BSRAM/DSP 计数。

## 案例 4 · 四声部齐按削顶（归一化必须在饱和之前）

**现象**：四键同时按下时破音。

**根因**：每个声部按单音满幅设计，四路相加超出 16 位范围；限幅器（saturate）把波形削成方波 → 严重的谐波失真。

**解决**：在 mixer 里**先按同时发声数缩放、再做饱和限幅**（1/1、1/2、21/64≈1/3、1/4），
用移位 + 加减实现，不引入除法器。

**启示**：
1. 多声部系统的"总能量预算"要在架构层解决，**不能指望限幅器兜底**；
2. 归一化放在饱和**之前**，限幅器就只在异常情况下起作用；
3. 21/64 与 1/3 相差约 0.045 dB——**用近似换硬件代价**是这类工程的常规取舍。

## 案例 5 · 按第二个键时一声"咔"（增益跳变）

**现象**：按住 A 正常；再按 B 出现一声"咔"，松开 B 又一声。清声（dry）更响却完全干净。

**定位过程**：
1. 先怀疑电平过大 → 用"Lo/Hi 电平开关"对比，**Lo 也破** → 排除模拟端过载；
2. 再查混合级：归一化系数是**按同时发声数**查表得到的，而计数一变化系数就**瞬间跳变** → 正在响的音幅度被瞬间砍半 → 一阶不连续 = 一次"咔"。

**根因**：增益是"阶跃"而不是"连续变化"。

**解决（两处）**：
1. 计数口径改为"**仍在发声**的声部数"（`gate | ADSR busy`）——否则最后一个音松开时计数立刻掉到 0，还在响的释放尾音会被放大 4 倍；
2. 增益改成**每样本限幅步进的斜坡**（Q15、每样本最多变 128，约 2.7 ms 走完 1/1→1/2）。

**启示**：
1. **任何"按条件切换的增益"都要考虑它切换时对已有信号做了什么**；
2. 排查音频问题要**先做对照实验**（Lo/Hi、冻结 LFO），再改代码——对照实验比猜快得多；
3. 斜坡的代价是"变化变慢"，在演奏类系统里这通常是可以接受的。

## 案例 6 · 松开最后一个音，尾音突然变大

**现象**：多声部归一化做好之后，最后一个音松开的瞬间尾音音量跳一下。

**根因**：归一化统计的是 `gate`（按键状态），而 note_off 之后 gate 立刻变 0 → 计数 4→0 → 系数从 1/4 跳回 1/1，
**但此时三个声部的 ADSR 释放还没结束**，还在发声 → 尾音被瞬间放大。

**解决**：统计口径改为 `gate | busy`（busy 来自 ADSR 的"仍在发声"标志），尾音收完计数才归零。

**启示**：**"信号存在"和"信号有声"是两件事**。做动态资源统计时，要选与"听觉上还在发声"一致的那个口径。

## 案例 7 · 叠置和弦丢音，且看起来"随机"

**现象**：按住 A 的和弦再按 B 的和弦，松开 B 后 A 的和弦只剩一个音，而且**每次剩下的音不一样**，偶尔完全不响。

**定位过程**：把声部分配器的行为逐拍推演出来——

| 事件 | 4 个声部的占用 |
|---|---|
| 按 A | v0=60, v1=64, v2=67 |
| 按 B 第 1 音 64 | v3=64 |
| 按 B 第 2 音 68 | 无空闲 → **抢占 v0**（A 的根音被顶掉） |
| 按 B 第 3 音 71 | 无空闲 → **抢占 v1**（A 的三度被顶掉） |
| 松 B → 发 64/68/71 的 note_off | v3/v0/v1 被释放 |
| 结果 | 只剩 v2=67（A 的五度） |

**第二个隐藏问题**：释放是按 `note_id` 匹配的，而 A 的 E4 与 B 的根音都是 64 → 松开 B 会**误杀 A 的 E4**。

**根因**：4 个声部放不下两个三音和弦（6 音）；"叠加和弦"这个交互语义本身就超出了当前的声部预算。

**解决**：**改交互语义**——同一时刻只允许一个和弦在响，采用"**最近按下优先**"（last-note priority）：
按住 A 再按 B 响 B；松开 B 回到 A；换和弦时先释放旧和弦、等 ADSR 释放结束（约 34 ms）再起新和弦。

**启示**：
1. **资源不足时，"改需求"往往比"堆资源"更好**：不扩声部、不动共享模块，问题从根上消失；
2. 多声部系统里 **note_id 是"释放匹配键"**，不同来源共用同一 id 会互相误杀——这是设计接口时就要想清楚的事；
3. 行为要可预期：**随机丢音是最糟的体验**，宁可限制功能也要确定。

## 案例 8 · 合唱持续破音（本工程最有价值的一次排查）

**现象**：开启合唱后，正弦**单音**也持续破音；清声（dry）比合唱更响却完全干净。

**定位过程（教科书式的三步）**：
1. **排除电平**：dry 更响不破 → 不是过载、不是"相加忘了除 2"（源码里本来就是 `(dry + wet) >> 1`）；
2. **确认是合唱支路**：单音也破、和弦也破、dry 不破 → 问题 100% 在 `chorus.v` 内部；
3. **对照实验**：把 LFO 步长设为 0（延迟冻结不动）→ **破音消失** → 锁定"读指针在动"这件事。

**根因**：延迟读指针是**整数样本步进**——LFO 每 256 个样本让延迟量跳 1 个样本（≈ 5.3 ms 一次），
等于在波形上周期性插入一阶不连续点，重复频率约 **187 次/秒** → 听感就是持续的粗糙/破音。

**解决**：改成**分数延迟 + 线性插值**——LFO 拆成 8 位整数部分 + 8 位小数（Q8），
每样本取相邻两个抽头 `a`、`b`，输出 `a + (b − a) × frac`；两个抽头用同一存储端口分时读。
代价：+1 个乘法器（DSP 3→3.5 块）、BSRAM 7→9 块、Logic +110。

**启示**：
1. **可听现象必须转成可测量的量**（"每 5.3 ms 跳一次"就是可测的）；
2. **对照实验是最快的定位手段**（冻结 LFO 一下就把范围从"整个音频链路"缩到"读地址"）；
3. **标准解往往就是"别人为什么那样做"**：专业合唱都做分数延迟插值，不是炫技，是因为整数步进必然产生这种失真；
4. 改造过程中我自己一度改出**丢掉 dry/wet 混合**的错误（输出变成 100% 湿声），是测试台抓出来的 → **改造要有测试兜底**。

## 案例 9 · 综合器把顶层选错，P&R 报"所有端口都找不到"

**现象**：布局布线阶段报 `Can't find object named 'clk' / 'key_n[0]' …`——**每一个**端口都找不到。

**定位过程**：报错信息指向"约束"，但真正的问题在综合：日志末尾写着
`NOTE (EX0101) : Current top module is "input_map"` ——综合器把一个**已不再使用、但还留在工程文件清单里**的模块当成了顶层。

**解决**：① 把不再使用的源文件移出工程清单；② 在工程配置里**显式指定** `TopModule`。

**启示**：
1. **报错的位置 ≠ 原因的位置**。P&R 报的是"结果"，要回到综合日志找"起点"；
2. 工程越大越要**显式声明顶层**，不要依赖工具自动识别；
3. 清理"不再使用的源文件"是工程卫生，不是小事。

## 案例 10 · 一个被误判的警告：`is swept in optimizing`

**现象**：综合警告说某个实例被"优化掉"，我们担心功能被删。查了层次报告、网表、引脚表都判不出来。

**解决**：**用一块位流上板验证**——按键功能正常，说明逻辑只是被**内联进父模块**，警告无害。

**启示**：
1. 警告分两类："逻辑被真的删掉"和"层次被展平"；**资源计数（BSRAM/FF）能区分**（真的删掉会掉资源）；
2. 判不出来时，**用最小的实机验证一次性定性**，比继续猜更省时间；
3. 记录这类"虚警"能避免下次重复调查。

## 案例 11 · 专用引脚（SSPI）不能随便用

**现象**：同一个引脚在其他工程能用，新建工程却报
`ERROR (PR2017): 'i2s_din' cannot be placed according to constraint, for the location is a dedicated pin (SSPI)`。

**根因**：PIN54–56 属于外部配置 Flash 的 SSPI 专用引脚；旧工程在 GUI 里勾选过"放开 SSPI"，而新工程是默认配置。

**解决**：把旧工程的 `impl/<project>_process_config.json` 复制到新工程并把 `"SSPI"` 设为 `true`。

**启示**：
1. **引脚能不能用，常由"工程配置"决定，而不是代码**；
2. 新建工程时要**对照一个已验证工程**核对配置项，别从零开始。

## 案例 12 · 工程配置不在版本库里（可复现性陷阱）

**现象**：`impl/` 目录整体被 `.gitignore` 排除，但**关键工程设置（SSPI、顶层、输出文件名）恰好存在那里**。
照仓库重建工程时，会重现案例 9 / 11 的错误。

**解决**：把"必须在 GUI/工程配置里设置的项"整理成清单写进文档；新工程建立后逐项核对。

**启示**：**版本库里的代码 ≠ 完整的工程**。可复现性要专门检查"哪些设置在代码之外"。

## 案例 13 · 测试台"全绿"却抓不到错（空跑）

**现象（三种）**：
1. 长回波用例用"采样 `valid` 电平"判断——而下一轮 TRIG 已经把它清掉了，**检查被绕过**；
2. 测试台数组按 3 个脉冲分配，后面越界读到 `x`，报出一堆假 FAIL；
3. 改了 DUT 的流水深度（3 拍 → 4 拍），测试台还在按旧拍数等 → 全部读到 0。

**解决**：① 用"**上升沿计数**"等随时间稳定的判据，不用瞬时电平；② 数组按最大脉冲数分配；
③ 测试台改成**等有效脉冲**而不是数固定周期。

**启示**：
1. "测试通过"本身也需要被验证——**变异测试**（故意把 DUT 改坏，确认测试台会红）是有效手段：
   本工程对超声波（改错距离常数）与测试模式（改错频率表）各做过一次，都成功抓到；
2. 测试台的判据要选**不会被时间边界影响**的量；
3. **改动 DUT 的时序结构必须同步测试台**，否则测的是过期期望。

## 案例 14 · 异步输入的亚稳态与"两级同步"为什么够

**现象**：超声波 ECHO 是外部异步信号，边沿可能正好落在时钟沿附近。

**解决**：两级同步器（`echo_s0 → echo_s1 → echo_s1d`），状态机**只使用同步后的值**和由它派生的边沿脉冲。

**为什么够**：亚稳态概率随同步级数指数下降；**这个概率仿真证明不了**，只能靠结构与时序约束保证。
另外：上升/下降沿经过**同一组同步器**，延迟相互抵消 → `t_fall − t_rise` 只留 ±1 µs 量化误差。

**启示**：
1. 跨时钟域/异步输入的处理是**结构问题**，不是"多仿真几次"能解决的；
2. 设计时要主动利用"共模抵消"这类性质（同路径延迟在差值里消掉）。

## 案例 15 · 要不要用 MCU 分担显示？（合规判断的方法论）

**问题**：OLED 刷新与波形动画会不会拖垮 FPGA？能不能外挂 STM 分担？

**定位过程**：**先查官方原文，再谈技术**。用 pypdf 提取《选题指南》文本后按行核对：
——"不使用 MCU"出现在**选题四（开放型题目）**；选题二（我们的选题）的红线全部围绕
**音频生成通路**（HDL 逐样本、≤10 ms、杜绝软件串行运算、严禁预录/推流/整段触发）。

**结论**：① 官方未禁止固定功能专用芯片（DAC、显示驱动、ADC、触摸控制器都是外围器件）；
② 我们自己的 `AGENTS.md` 定了更严的规矩（最终作品不含任何可编程器件参与功能），因此**保持纯 FPGA**；
③ 调试阶段允许临时用其他 MCU 做采集/信号发生，但不得进入位流、PCB、BOM 与报告。

**启示**：
1. **合规问题先查原文，不凭印象**；引用要能定位到行；
2. 自定约束可以比官方更严，但要写清边界（"固定功能器件" vs "可编程器件"）；
3. 答辩口径要提前写好：*"本作品唯一的可编程器件是 FPGA，音频链路的每一级都是 HDL 硬件逻辑；板上其他芯片都是固定功能专用器件。"*
