## 2. 作品形态 ✅

**名称：吟游 Loom —— 基于 Tang Nano 20K 的纯硬件实时多音色合成电子乐器引擎**

### 2.1 产品定位

一台**能真的弹、能听出表情、能现场被验证**的桌面合成器。不是「演示板」，是「乐器」。

### 2.2 三个必须做到的能力

**① 声部引擎（FPGA 纯 HDL）**

- 每个声部 = `独立相位累加器 + 频率控制字 + ADSR 包络` ← 严格对齐赛题 R1 振荡器判据
- 波表合成：多张单周期波表（正弦 / 三角 / 锯齿 / 方波）
- 波形与参数运行时可变，支持单音实时变调
- 主输出：逐样本混音 → 饱和限幅 → I2S → 板载 MAX98357A → 小喇叭
- **复音：基础 4，可参数化扩展至 8** ✅

**② 演奏交互（≥2 维，目标 3 维）**

| 维度 | 器件 | 映射 | 状态 |
|---|---|---|---|
| D1 音高选音 | 自研铜箔电容触摸（RC 测时） | 音名 / 选音 | 目标 |
| D2 力度 | 按键按下时长 / 触摸面积 / 外接按键或摇杆档位（待定 ❓） | 音量 + 亮度 | 目标 |
| D3 连续表情 | 自研超声波测距 | 滑音 / 揉弦 / 表情量 | 目标 |
| 保底通路 | 板载 2 按键（KEY_S1=PIN88 / KEY_S2=PIN87）；4 音和弦需外接按键模块 | 触发 / 选音 | 保底 |

> 赛题原文是「任意**自研交互方案**」——指自研的**交互形态与逻辑**，不要求自研传感器。
> 本方案的自研前端（触摸 + 超声波）是差异化重点；板载 / 外接按键是稳定保底。

**③ 可验证性（很多队伍会死在这里）**

- `TEST_MODE` 开关：一键让 N 个振荡器输出互不成谐波关系的固定频率
- 频谱 App 对着喇叭拍 → 谱峰数量可数
- RTL 代码可现场翻阅 → 证明无预录 PCM
- **这个模式从第一天就写进架构，不能最后补**

### 2.3 拓展要求打哪几条 ❓

| 拓展项 | 目标 | 成本 | 建议 |
|---|---|---|---|
| E1 复音 ≥32 | 冲刺目标：先确认 8，再冲 16 / 32 | 中–高（取决于综合 / 时序） | 🎯 **P4 综合后决定** |
| E2 ≥3 维 + ≥2 音色 + 效果器 | 3 维 + 2 音色 ✅；效果器冲刺：合唱 → 延迟 → 混响 | 中 | 🎯 **合唱 / 延迟至少一个** |
| E3 ≤5ms + 视听反馈 | 冲刺 ≤5ms + LED 视觉；OLED 可选 | 低–中 | 🎯 **P6 实测后决定** |
| E4 蓝牙 App | — | 极高 | ❌ **不打** |

### 2.4 一等奖冲刺清单（20K 专属，条件触发）🎯

> **前提：基础要求永远优先。** 任何冲刺项如果威胁到 ≥4 复音、≥2 维、≤10ms、ADSR、I2S 出声、无预录，立刻砍掉。

| 冲刺项 | 目标 | 最小版本（保底） | 砍掉条件 |
|---|---|---|---|
| E1 复音 32 | `VOICES=32` 综合 + 测试模式 32 谱峰 | 8 复音 + 综合报告论证可扩展 | 综合 / 时序放不下 |
| E2 效果器 | 合唱 + 延迟 | 合唱一个 | 时间不够，先保 E1 |
| E2 音色 | 3–4 种波表音色 | 2 种（已达标） | BSRAM 不够 |
| E3 ≤5ms | 实测 ≤5ms + 确定性 | 实测并文档化（≤10ms 已达标） | 测量边界含 DAC 后超 5ms |
| E3 视觉 | LED 演奏指引 / OLED 波形 | 板载 LED 电平 / 状态 | 时间不够 |
| 测试模式 32 | 32 路非谐波 + 相干采样 | 4–8 路可数谱峰 | 频率规划困难 |
| FPGA 基础考核 | Verilog 基础题练习 | 通过即可 | **不可砍（决赛门票）** |
| 报告 / 视频 | 实测数据 + RTL 导览 | 完整初赛材料 | **不可砍** |

> **新手提示**：你是第一次接触 FPGA，冲刺顺序建议是「先让 4 复音出声 → 8 复音综合 → 看到真实资源余量 → 再决定 32」。不要在没有综合报告之前承诺 32。

## 4. 技术架构

### 4.1 时钟与采样率 ✅（已生成 rPLL IP，参数精确）

```
板上 27MHz ──rPLL(IDIV=25, FBDIV=64, ODIV=8)──> 69.12MHz
                ├─ 每 15 拍翻转 ────────> BCLK  2.304 MHz
                └─ 每 1440 拍一个脉冲 ──> sample_en 48000.000 Hz（精确）
```

**关键公式**（官方 UG286 时钟资源用户指南）

```
f_CLKOUT = f_CLKIN × FBDIV / IDIV
f_VCO    = f_CLKOUT × ODIV          ← ODIV 不参与输出分频，只把 VCO 推入 400~1200MHz
f_PFD    = f_CLKIN / IDIV
```

**最终参数**

| 项目 | 值 |
|---|---|
| IDIV / FBDIV / ODIV | 25 / 64 / 8 |
| 系统时钟 CLKOUT | 69.12 MHz |
| VCO | 552.96 MHz |
| BCLK | 2.304 MHz（每 15 个系统时钟翻转一次） |
| LRCLK / 采样率 | **48000.000 Hz（精确，偏差 0）** |
| 每声声道槽位 | 24 bit（48 BCLK / LRCLK 周期） |
| 帧长 | 1440 个系统时钟 |

**方案演进记录**（避免重复踩坑）

| 阶段 | 方案 | 结论 |
|---|---|---|
| 初版 | 27MHz → 100.8MHz → ÷2100 | ✗ 需分频比 224/15 或 448/15，超 FBDIV ≤ 64 限制 |
| 中间版 | 39.9375MHz（FBDIV=71） | ✗ FBDIV 71 > 64，超限 |
| **最终** | **69.12MHz（25/64/8）** | ✅ 精确 48000.000 Hz |

> ⚠️ **两个坑**
> 1. **ODIV 的作用**：最初误以为 ODIV 是输出分频器，导致整套搜索错误。实际是 `f_VCO = f_CLKOUT × ODIV`。
> 2. **Gowin IP Wizard 会自动替换手填的分频参数**（偏好简洁比值，例如把 25/64 换成 9/23 = 69.0MHz）。
>    最终参数以 `fpga/loom/src/gowin_rpll/gowin_rpll.v` 的 `defparam` 为准，**不要再用向导重新生成**。

**额外好处**：`sample_en` 直接从 I2S 帧计数器派生，合成引擎与 I2S 发送天然同步，不需要 FIFO。

### 4.2 每个声部的资源预算（估算，需综合后校准）

| 资源 | 单声部 | 4 声部 | 8 声部 | 20K 总量 | 余量 |
|---|---|---|---|---|---|
| LUT | ~120 | ~480 | ~960 | 20736 | ✅ 充裕 |
| FF | ~55 | ~220 | ~440 | 15552 | ✅ 充裕 |
| BSRAM | 共享波表 | 共享 | 共享 | **828K bit（46 块）** | 需综合确认 |
| DSP | 0~1 | 0~4 | 0~8 | **48 × 18×18** | ✅ 充裕 |

> **关键结论：4/8 声部在 20K 上大概率放得下**，因为波表是**共享**的，只有相位 / 包络状态是每声部独立。
> 估算必须在 P4 用**真实综合报告**替换。
>
> ⚠️ 官方 PDF 只写「多个 18×18 DSP」，未给 DSP 数量；BSRAM 容量也需查 Gowin datasheet。

### 4.3 延迟预算（目标 ≤10ms，拓展 ≤5ms 暂不承诺）

| 环节 | 延迟 |
|---|---|
| 按键 / 触摸扫描 | 1ms（1kHz 扫描） |
| 声部分配 | 1 采样 = 0.021ms |
| 合成 + 混音 | 1~2 采样 ≈ 0.04ms |
| I2S 缓冲 | 1ms |
| DAC 重建 | ~1ms |
| **合计** | **≈3ms，全链路定长** |

> ❓ **测量边界待定**：从传感器变化算起？含不含 DAC 重建？P6 必须写清楚。

### 4.6 20K 资源策略（32 复音冲刺用）

| 策略 | 做法 | 为什么 |
|---|---|---|
| 波表共享 | 只放 1 份波表，所有声部分时读取 | 避免 BSRAM 随声部数增长 |
| 时分复用 | 每采样有 2100 个周期（100.8MHz / 48kHz），波表读、包络乘法、混音都可排队做 | LUT / FF / DSP 用量大幅下降 |
| 参数化 | `parameter VOICES` 支持 4 / 8 / 16 / 32 | 一份 RTL，多档综合对比 |
| 时序降频 | 若 100.8MHz 收敛困难，降到 50.4MHz（每采样仍有 1050 周期） | 保 48kHz 不变 |
| 效果器顺序 | 合唱 → 延迟 → 混响 | 存储 / 调试成本递增 |
| 回落方案 | 32 放不下 → 16 复音 + 效果器 + 报告论证可扩展 | 不让冲刺拖垮基础要求 |

> ⚠️ 以上都是**估算**，必须用 P4 的综合报告替换。20K 的 BSRAM / DSP 实际数量请查 Gowin datasheet / Sipeed wiki。

| 板载 MAX98357A 不工作 | 低 | 高 | 外接 I2S DAC 模块备份；或 PWM + RC 低通应急出声 |
| I2S 时序调不通 | 中 | 高 | 仿真波形先验证，再用 LED 打点定位 |
| 32 复音资源 / 时序不足 | 中 | 中 | 回落 16 复音 + 报告论证可扩展；优先保基础要求 |
| 效果器 / 视觉拖慢主线 | 中 | 中 | 按砍掉顺序：混响 → OLED → 延迟，保合唱 / 基础 |
| FPGA 基础考核不过 | 中 | 致命 | P1 / P2 阶段同步刷 Verilog 基础题 |
| 自研触摸不稳定 | 高 | 中 | **跳过 P5B**，用超声波 + 板载 / 外接按键保底 |
| 板载按键不足 4 个 | 高 | 中 | 板载仅 2 键；外接按键模块，或用自研触摸 / 超声波选音 |
| 时序不收敛 | 中 | 高 | 主频降至 50.4 MHz，采样率不变 |
| 文档 / 视频仓促 | 中 | 高 | P6 阶段就启动文档 |

## 8. 差异化卖点（报告叙事主线）

1. **小 FPGA 上的高资源效率**：在 20736 LUT4 的 Tang Nano 20K 上，用共享波表 + 时分复用把复音数从 4 推到 8 / 16 / 32（以综合报告为准），而不是靠堆资源。
2. **纯硬件合规**：全链路可指着 RTL 逐行讲，无一行软件、无一段预录。
3. **自研交互前端**：电容触摸 + 超声波测距都是自研电路，不是成品传感器模块。
4. **可现场验证**：TEST_MODE 让「振荡器数量」变成**肉眼可数的谱峰**。
5. **可伸缩架构**：同一份 RTL 改一个 parameter 就能扩展复音数，体现工程完备性。
6. **一等奖冲刺路线清晰**：32 复音、合唱 / 延迟、≤5ms 实测、LED / OLED 视觉，每项都有最小版本和砍掉顺序。
