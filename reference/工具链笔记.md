## 三、FT2232 EEPROM 配置（用 FT_PROG）

出厂是空白 EEPROM，两个通道默认都是 VCP 串口，Gowin 拿不到 JTAG 通道，表现为扫描卡死。修正配置：

| 通道 | Driver 设置 | 用途 |
|---|---|---|
| **Port A** | **D2XX Direct** | JTAG |
| **Port B** | **Virtual COM Port** | UART / 串口 |

操作要点：
- 用 **FT_PROG** 打开 `Device 0` → `Hardware Specific` → `Port A` → `Driver` → 选 `D2XX Direct`
- 同理把 `Port B` 设为 `Virtual COM Port`
- 点 `Program` 写入 → 点 `Cycle` 或拔插 USB 重新枚举
- **只改 Driver 选项**，不要动 VID/PID/字符串描述符
- 写入失败报 "device handle is not currently in use" → 是句柄被占用：关掉 Gowin Programmer、串口助手，杀掉残留进程，必要时重启电脑后**只开 FT_PROG**

## 四、Gowin Programmer 可用配置（已实测通过）


### 4.1 programmer_cli 的可靠烧录方式

本机实测：当 `.fs` 带 `SecurityBit: ON` 时，`programmer_cli --run 2`
可能显示编程进度到 100%，但随后报 `User code mismatch`；再次读取设备时
`User Code` 仍为 `0` 或 `FFFFFFFF`，说明配置没有真正写入。

改用纯 JTAG 1149 模式可以正常配置 SRAM：

```powershell
& 'C:\Gowin\Gowin_V1.9.11.03_Education_x64\Programmer\bin\programmer_cli.exe' `
  --device GW2AR-18C `
  --operation_index 16 `
  --fsFile 'C:\Users\ReachGao\Desktop\CodeX\loom\fpga\loom\impl\pnr\loom.fs' `
  --cable-index 4 `
  --frequency 2.5MHz
```

烧录后必须再执行一次读设备代码确认：

```powershell
& 'C:\Gowin\Gowin_V1.9.11.03_Education_x64\Programmer\bin\programmer_cli.exe' `
  --device GW2AR-18C --operation_index 0 --cable-index 4 --frequency 2.5MHz
```

`0x0000C208`，P5A 双键音量对照位流为 `0x00002630`；配置成功时

## 五、JTAG 时钟（TCK）的"甜区"

**关键结论：扫描卡死不一定是时钟太快，反而可能是太慢。**

实测：TCK = 0.5MHz 时 `Scan Device` 卡在 50%，点停止无响应，必须杀进程；改成 **2.5MHz 后正常**。

原因不是信号完整性，而是**超时**：读 IDCODE 要移几百到上千位，主机侧等待窗口固定；TCK 太慢时扫描耗时会超过窗口，主机认为设备无响应，界面停在 50%。另外 FT2232 的 USB latency timer / 分包节奏在极慢 TCK 下也容易对不上。

| TCK | 典型症状 |
|---|---|
| 10MHz 以上 | 信号完整性不足：校验错误、随机失败 |
| **1 ~ 5MHz** | **甜区，最稳** |
| ≤ 0.5MHz | 超时、界面卡死、必须杀进程 |

**遇到卡住时，在 0.5 / 1 / 2.5 / 5 / 10 MHz 之间依次试，不要一味降频。**

## 六、故障排查速查表

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `Scan Device` 卡在 50%，无法停止 | TCK 太慢导致超时 | 把 TCK 提到 2.5MHz |
| Programmer 里电缆显示 `.../null` | EEPROM 空白或通道未配成 D2XX | 用 FT_PROG 设 Port A = D2XX |
| FT_PROG 报 "handle is not currently in use" | 设备被其他程序占用 | 关 Gowin / 串口助手，杀残留进程，重启后只开 FT_PROG |
| 扫描不到任何设备 | USB 线只充电不传数据 / Hub 干扰 / 按键被按住 | 换数据线、直插 USB 2.0 口、上电时松开 KEY_S1/S2 |
| 综合报 `CT1136 Bank vccio conflicting LVCMOS18` | `.cst` 里 IO_TYPE 写成 1.8V，而 Bank 6/7 实际 3.3V | 把该 Bank 的 `IO_PORT` 改为 `IO_TYPE=LVCMOS33` |
| 烧录成功但板子无反应 | 只做了 Load，没做 Program；或烧的是别的文件 | 确认 Operation = SRAM Program 且点了 Program |
| P&R 报 `PR2017 ... dedicated pin (SSPI)` | 该引脚默认被配置功能占用 | `Project → Configuration → Dual-Purpose Pin` 勾选 **`Use SSPI as regular IO`**，然后**重跑 Synthesize** 再 P&R |
| P&R 报 `PR2028 constrained location is useless in current package` | 同上，引脚在当前封装下不可作为普通 IO | 同上；或换到排针上的自由 IO |
| 综合报 `SORT-1002 cannot open .../??/...` | 工程路径含非 ASCII 字符 | 把工程放在纯英文路径下（本仓库已改为 `C:\Users\ReachGao\Desktop\CodeX\loom`） |
| OLED 黑屏但 I2C 有波形 | 初始化序列与控制器不匹配 | 该模块手册自相矛盾（机械图写 SSD1306，命令章节写 SH1106）。`oled_demo_top` 里按住 S2 再按 S1 可切换到 SSD1306 序列；LED2 灭表示 SSD1306 模式 |
| I2C 从机完全无响应 | 主机每发一字节就 STOP，控制/数据字节被当成新地址 | 主机必须支持"一次事务多字节"：`first`/`last` 标志控制 START/STOP，字节之间保持总线 |
| P3 音频响几秒后停止，随后配置丢失 | 喇叭两个输出临时触点相碰或碰到 `GND`，MAX98357A 拉大电流导致 FPGA 复位 | 断电后分开并固定两个输出触点，确认不与地或 20P 排针短路，再用 `--run 16` 重新烧录 |
